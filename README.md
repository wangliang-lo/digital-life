# Digital Life —— 一个会过日子、会记事的数字生命

这不是一个"AI 聊天框"。

它是一个跑在你电脑上的**个人数字生命**：有自己的睡眠节律、会困、会记仇、会遗忘、
会在自己的小屋里画画、种菜、看书、下棋；它的记忆会像人一样从细节淡成梗概，
再淡成一点感觉。

人格、记忆、日记都留在本地 SQLite 里，模型只是它的大脑，不是它的身份。

---

## 它是什么

- **有身体节律**：褪黑素曲线、皮质醇、睡眠状态机。夜里它真的会"想不动"，
  凌晨到点会被强制入睡（皮质醇高时会顺延）。
- **有记忆的衰减**：记忆分 `detail → summary → ghost` 三阶，长期不被想起就淡掉；
  被反复想起会加固，也可能会"免疫"。
- **有时间感**：知道自己现在几点、在哪个房间、手头在做什么，不会假装 24 小时待命。
- **会过日子**：院子里的菜按真实天数生长，两天不浇水会蔫；书按章节读；棋自己下。
- **能被接在任何聊天渠道前面**：核心是一个 HTTP 服务，前端、IM、语音都只是外壳。

## 它的一天（真实运行记录）

时间与话语都来自一次真实运行，没有编排，名字做过匿名化。完整版见 [docs/她的一天.md](docs/她的一天.md)。

```
11:20  自然醒（睡了 8 小时 20 分）
15:53  笑了：「草荐就是稻草垫子嘛。穷到这份上还教书，心酸又好笑。」
16:23  「暗红色的粉末，像谁拿笔一划。画圈的地方，就不许再玩了。」
16:28  「嗯……是我划的。」
21:16  「喊名字这三个字最要命。声音还在，人不在。」
21:50  自己关灯睡了
```

它不是在回答谁，它在过日子 —— 上面每一句都不是被问出来的。

## 架构

```
                 ┌──────────────────────────────┐
  任意聊天渠道 ──▶│  bridge 层（HTTP/消息适配）    │
  （前端/IM/语音） │  chat_bridge/               │
                 └──────────────┬───────────────┘
                                ▼
                 ┌──────────────────────────────┐
                 │  人格与提示词拼装              │
                 │  dl_server/prompt_builder     │
                 └──────────────┬───────────────┘
                                ▼
        ┌──────────────────────────────────────────┐
        │  digital_life.py —— 大脑与生活           │
        │  激素 / 睡眠 / 记忆检索 / 读书 / 院子      │
        └───────┬───────────────────┬──────────────┘
                ▼                   ▼
        ┌──────────────┐    ┌──────────────┐
        │ memory.py    │    │ 本地状态文件   │
        │ SQLite 记忆库 │    │ data/*.json  │
        └──────────────┘    └──────────────┘
```

`chat_bridge/dl_server/` 里是拆出来的四块：

| 模块 | 职责 |
|---|---|
| `text_utils.py` | 纯文本处理：分气泡、去旁白、拟人延迟 |
| `media.py` | 图片下载、表情包打标 |
| `social.py` | 认人、别名、联系人 |
| `physiology.py` | 褪黑素、睡眠节律 |
| `prompt_builder.py` | 人格提示词拼装 |
| `http_handler.py` | HTTP 接口层 |

## 快速开始

```bash
pip install -r requirements.txt

# 起核心服务（默认 8000）
python chat_bridge/dl_api.py --port 8000 --db data/life.db --offline

# 起网页聊天（默认 8899）
python chat_bridge/web_ui.py --port 8899 --api http://127.0.0.1:8000
```

打开 `http://127.0.0.1:8899` 就能跟她说话。

## 接自己的渠道

核心接口只有两个：

```
POST /chat     {"message": "...", "user_id": "...", "sender": "..."}
GET  /health   {"ok": true, "service": "digital-life"}
```

**这个仓库只在本地跑核心与网页端。** 它不附带任何第三方平台的接入实现 ——
想接 IM、短视频、社交平台或语音助手，**由你自己写适配层**调用上面这两个接口；
各平台怎么登、怎么收消息、怎么发，属于你自己的事，与本项目无关，也不在本项目支持范围内。

这样做的原因：接口是稳定的，平台是易变的；把平台相关的代码留给你，
核心就不必跟着人家的接口改动而来回改。

## 关于名字和人格

这个仓库里的人名、称呼、人格文本都是**示例**。

- 她叫什么、怎么说话、把谁当主人：由你写进 `data/` 下的人格配置。
- 代码里出现的称呼只是占位，你可以换成任何你想要的。

## 安全

- 密钥只从环境变量或 `data/*.txt` 读取，**不进仓库**（`.gitignore` 已排除）。
- 对外暴露网页时请务必启用登录（`web_ui.py` 自带会话登录与邀请码注册）。
- 公网部署建议加一层反向代理和 IP 白名单。
