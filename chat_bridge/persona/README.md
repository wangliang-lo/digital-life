# 语料包：让她一开口就像人

## 这是什么

两个文件，控制「她怎么说话」：

| 文件 | 内容 | 影响 |
|---|---|---|
| `voice.md` | 说话规则，每行 `- ` 一条 | 长度、开头、结尾、什么不说、什么可以说、分寸 |
| `samples.json` | 按场景分的短语料 | 断句和口气的参考 |

它们会被拼成提示词里的一个块：

```
【语感】说话照这个来，不是任务，是你本来就有的习惯：
一句能说完，就别拆成三段；说完就停……
【语感样例】只学断句和口气，别照抄原句：
- 被损：「对对对，就你不是 AI。」/「你这帽子扣得挺顺手啊。」
```

**改完不用重启**，下一轮对话就生效（按文件修改时间缓存）。

---

## 为什么要「语料」而不是「规则」

只给规则，她会照着规则**演**——你越写「要短」，她越会写出「我短。我说完了。」这种。

给语料，她学的是**节奏**：哪里断、哪里停、什么时候一个「嗯」就够了。

所以 `samples.json` 里全是短句，不解释、不铺垫、不总结。

---

## 设计上的几个取舍

**1. 样例不全塞，按小时轮换**

每轮只带 2 个场景、每场景 3 条，**按小时轮换**（不是每轮随机）。

为什么：每轮都变会让提示词的前缀缓存失效，白烧钱；一小时换一次，既有变化又命中缓存。

**2. 场景按情绪切，不按话题切**

`被损` `接梗` `无聊敷衍` `认真短答` `安慰` `拒绝` `自言自语` `被夸` `不知道`

人说话是被情绪驱动的，不是被话题驱动的。同样是聊书，心情好和心情差是两种说法。

**3. 规则每条都要能单独读懂**

`voice.md` 里的条目会被拼成一段话（用「；」连）。所以：

- ✅ `不说「首先」「其次」`
- ❌ 在「## 不要说」下面只写「首先」「其次」——拼起来就变成了「要用这些词」

**4. 分寸写在语料里，不写在过滤器里**

`开玩笑刀口朝上，朝事情、朝规则、朝自己；不朝别人的痛处。`

这句话比十个关键词黑名单管用。因为她要理解的是**方向**，不是**词表**。

## 想加自己的语料

改 `samples.json`，加场景或往现有场景里加句子：

```json
{
  "scenes": {
    "困了": ["眼皮打架", "再说我就睡着了", "几点了"]
  }
}
```

句子越短越好。超过 20 个字就不像口语了。

**别抄贴吧原话。** 学的是断句方式，不是内容。贴吧一半的内容是开盒、地域黑、拿人痛处玩梗——那些会让「人味」变味。
